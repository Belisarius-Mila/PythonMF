================================================================
  STEP 5 — step5_weekdays.py
================================================================

CELKOVÉ HODNOCENÍ
  Nejkomplexnější a nejkvalitnější krok dosud — tři módy,
  persistentní barvy, edit distance, SingleFlightTTS,
  replace_process. Vidět jak architektura zraje.

────────────────────────────────────────────────────────────────
🔴 ZÁVAŽNÉ PROBLÉMY
────────────────────────────────────────────────────────────────

1. _write_user_color_prefs — nebezpečný write bez atomicity
   Přepis celého CSV jedním open("w") — pokud dojde k výjimce
   uprostřed zápisu (disk plný, přerušení), soubor zůstane
   poškozený nebo prázdný.
   Řešení: zapisovat do dočasného souboru a pak rename():
     tmp = prefs_path.with_suffix(".tmp")
     with tmp.open("w", ...) as handle:
         writer.writerows(retained)
     tmp.replace(prefs_path)  # atomická operace

────────────────────────────────────────────────────────────────
🟡 STŘEDNĚ ZÁVAŽNÉ PROBLÉMY
────────────────────────────────────────────────────────────────

2. _run_sequence — timing stejný problém jako autoplay v step4
   Pevný timeout 1800ms — u kratších slov (IT: "lunedì") TTS
   skončí za 600ms a zbytečně čeká. U delších (FR: "mercredi")
   může přechod nastat dřív než TTS dohraje.
   Řešení: konzervativnější timeout nebo TTS callback.

3. assert v produkčním kódu
   assert isinstance(entry, ctk.CTkEntry)
   assert isinstance(result, ctk.CTkLabel)
   assert se přeskočí při spuštění s -O (optimize flag).
   Řešení: explicitní if not isinstance(...): return
   nebo prostě důvěřovat struktuře write_rows dict.

4. _color_name_map — duplicitní hardcoded HEX mapa
   Stejná mapa jako COLOR_HEX_BY_CZ v step4, nyní na dvou
   místech s mírně odlišnými hodnotami (case rozdíl:
   step4: #ef4444, step5: #EF4444).
   Předem odsouhlasený technický dluh — poznamenáno
   pro budoucí refaktor.

────────────────────────────────────────────────────────────────
🟢 DROBNOSTI
────────────────────────────────────────────────────────────────

5. Klávesové zkratky chybí v step5
   Step3 a step4 mají <space>, <Right>, <Left>.
   Step5 nemá žádné — nekonzistence pokračuje.

────────────────────────────────────────────────────────────────
✅ POZITIVA
────────────────────────────────────────────────────────────────

- _edit_distance: čistá iterativní Levenshtein implementace
- is_navigating flag: zabraňuje dvojitému replace_process
- write_after_ids list: správný cleanup after() ID při zavření
- _next_sequence: elegantní modulo pro cyklické procházení


================================================================
  SCREEN_FRAMES — screen_frames.py
================================================================

CELKOVÉ HODNOCENÍ
  Klíčový architektonický soubor — frame-based navigace místo
  subprocess řetězení. Záměr správný a provedení solidní.
  Ale jsou tu dva zásadní strukturální problémy.

────────────────────────────────────────────────────────────────
🔴 ZÁVAŽNÉ PROBLÉMY
────────────────────────────────────────────────────────────────

1. Cyklické importy — časovaná bomba
   screen_frames.py importuje ze step3, step4, step5:
     from step3_flashcards import _build_asset_index, ...
     from step4_colors import _build_assets, ...
     from step5_weekdays import _build_weekdays, ...
   Zatím funguje, ale je to křehké — jakákoli změna importů
   v step3/4/5 může způsobit cyklický import a crash při startu.
   Správná architektura: logika (_build_flashcards,
   _build_weekdays...) by měla být v samostatném core.py nebo
   logic.py modulu, který importují jak standalone skripty
   tak screen_frames.

2. Import privátních funkcí (_funkce) napříč moduly
   from step3_flashcards import _build_asset_index, _placeholder_image
   from step4_colors import _build_cards as build_color_cards
   Funkce s prefixem _ jsou konvencí označeny jako privátní.
   Jejich import přes moduly vytváří těsnou závislost —
   jakákoli refaktorace internálů step3/4 okamžitě rozbije
   screen_frames. Přímý důsledek bodu 1 — chybí sdílená
   logická vrstva.

────────────────────────────────────────────────────────────────
🟡 STŘEDNĚ ZÁVAŽNÉ PROBLÉMY
────────────────────────────────────────────────────────────────

3. _save_day_colors v WeekdaysScreen bez error handlingu
   Na rozdíl od standalone WeekdaysApp kde byl try/except
   a status label zpráva — zde žádný error handling není.
   Pokud zápis selže (disk plný, permissions), uživatel
   se nedozví nic.

4. WeekdaysScreen user selector — nekonzistentní formát
   Standalone zobrazuje: "me - Já"
   Screen frame zobrazuje jen: "me"
   Nekonzistentní UX mezi embedded a standalone verzí.

5. FlashcardsScreen — chybí destroy() override
   ColorsScreen a WeekdaysScreen mají destroy() s cleanup
   logiky. FlashcardsScreen ho nemá — nekonzistentní vzor.

────────────────────────────────────────────────────────────────
🟢 DROBNOSTI
────────────────────────────────────────────────────────────────

6. APP_TITLE importován ale nepoužit:
   from step4_colors import APP_TITLE as _UNUSED_COLORS_TITLE
   Stačí odstranit z importu.

────────────────────────────────────────────────────────────────
✅ POZITIVA
────────────────────────────────────────────────────────────────

- _poll_sequence_controls: elegantní polling TTS busy stavu
  přes after(120) pro unlock tlačítek — čistší než pevný timeout
- is_leaving flag: konzistentní se standalone verzí
- _finish_back + after_idle: explicitní destroy write_frame
  před návratem zabraňuje memory leak scrollable framu
