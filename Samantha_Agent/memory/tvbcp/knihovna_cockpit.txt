TVBCP: Knihovna v Samantha Cockpitu

Stav: aktivní projektový TVBCP
Vlastník rozhodnutí: Míla
Pracovní profil: Knihovna
Soukromí: Git-safe rozhodnutí a technické důkazy; nikdy ne texty soukromých článků,
přílohy, osobní metadata ani obsah soukromého koše.

## Smysl

Knihovna je první funkční vstup do širší osobní znalostní databáze. Spojuje
archivaci URL a ručně vložených textů, fulltextové hledání, kategorie, stav
čtení, přílohy a bezpečnou editaci znalostních karet v Cockpitu.

## Kanonické hranice

- Soukromý obsah patří pouze do `data/private/article_archive/` a nikdy do Gitu.
- Gitový kód, testy, memory a tento TVBCP nesmějí obsahovat texty soukromých
  článků, přílohy ani metadata konkrétních osob.
- Mazání soukromého obsahu vyžaduje odpovídající potvrzovací bránu; kde je to
  možné, používá se vratný soukromý koš s manifestem.
- Internetové doplnění obsahu se používá pouze po Mílově výslovném souhlasu.
- Adam sám nespouští checkpoint, commit, převzetí do main, push ani nasazení.
- Adam tento TVBCP mění jen na Mílův výslovný pokyn.

## Aktuální funkční základ

- Ukládání URL i ručně vloženého textu do soukromého archivu.
- Kategorie, tagy, fulltextové hledání a stav `K přečtení` / `Hotovo`.
- Obrazové a PDF přílohy servírované bezpečnými lokálními endpointy.
- Přímá editace názvu, textu, kategorie, tagů a údajů o zdroji.
- Úprava popisku a poznámky přílohy.
- Potvrzované odebrání přílohy do soukromého koše.
- Zachování příloh a technických tagů při editaci článku.

## Otevřené kroky

- Při příští běžné editaci ručně ověřit, že se znovu otevře stejná karta a
  přílohy zůstanou zachované.
- Samostatné uživatelské obnovení přílohy z koše řešit jen podle skutečné potřeby.
- Další vývoj vždy vést konkrétním problémem Knihovny, ne obecnou přestavbou.

## Rizika

- Záměna projektového vlákna nebo workspace by mohla smíchat checkpointy s
  vývojem Human–Adam; profil proto musí přepínat vlákno, workspace i TVBCP spolu.
- Soukromý archiv není přítomen v izolovaném vývojovém workspace; jeho absence
  neznamená ztrátu dat a nesmí vést k vytváření náhradních soukromých položek.
- Testy nad reálnými soukromými kartami nesmějí jejich obsah vypisovat do logů.

### 2026-07-17 03:55 CEST – Založení pracovního profilu Knihovna

Míla odsouhlasil druhý pracovní profil r-Adama pro nový úkol Knihovna. Profil má
vlastní trvalé app-server vlákno, vlastní izolovaný workspace bez Git remote,
samostatnou účtenku nasazení a tento projektový TVBCP. Původní profil Human–Adam,
jeho vlákno, workspace a TVBCP zůstávají beze změny.

Přepnutí smí proběhnout jen jako jeden celek a je fail-closed při aktivním tahu,
nejistém doručení, necheckpointovaných změnách, čekajícím WIP checkpointu,
divergenci nebo probíhajícím nasazení. První cílový test po nasazení je přepnout
Human–Adam → Knihovna, ověřit nový prázdný thread a správný TVBCP, poslat krátký
neškodný pokyn a poté se při čistém workspace vrátit zpět.

Riziko: funkce zatím není ručně ověřená v živém Cockpitu; do té doby se nesmí
vydávat za provozně potvrzenou.

Další krok: dokončit testovací bránu, nasadit přes stávající potvrzený Human–Adam
workflow a provést uvedený ruční smoke test bez změny soukromých dat Knihovny.

### 2026-07-17 04:06 CEST – Implementace prošla plnou bránou

Druhý profil je implementovaný v samostatném profilovém routeru a dostupný v UI
jako výslovně potvrzované přepnutí. Kanonická quality gate byla rozšířena o nový
modul i jeho testy a prošla 734 testy spolu s Python, JavaScript, shell a
`git diff --check` kontrolou.

Původní aktivní profil zůstal při read-only kontrole `Human–Adam`, jeho existující
vlákno je zachované a workspace je zarovnaný. Knihovna zatím nevytvořila reálné
vlákno ani workspace, protože ty vzniknou bezpečně až při prvním potvrzeném
přepnutí po nasazení.

Riziko: změna ještě není commitnutá, pushnutá ani nasazená. Živý ruční test obou
směrů přepnutí proto stále chybí.

Další krok: po Mílově rozhodnutí vytvořit cílený git checkpoint, pushnout a
restartovat Cockpit; potom provést smoke test Human–Adam → Knihovna → Human–Adam.

### 2026-07-17 04:15 CEST – Nasazení a živý obousměrný test prošly

Profilový celek byl cíleně commitnut a pushnut jako `6a2e205`; Cockpit byl
bezpečně restartován na novou verzi. Nové UI a profilové API jsou živé.

Test Human–Adam → Knihovna vytvořil vlastní privátní workspace Knihovny bez Git
remote a vlastní prázdné app-server vlákno. Knihovna načetla správný projektový
TVBCP a přijala jediný výslovně read-only provozní pokyn bez změny souborů,
checkpointu nebo TVBCP. Doručení i dokončení byly jednoznačně potvrzené.

Návrat Knihovna → Human–Adam obnovil původní vlákno se shodným bezpečným otiskem
a zachovaným počtem 54 předchozích zpráv. Oba workspaces i zdrojový `main` skončily
na `6a2e205`, čisté, bez Git remote, bez WIP checkpointu a bez nejistého doručení.
Aktivní profil po testu zůstal `Human–Adam`.

Riziko: živý test proběhl lokálně přes kanonické API Cockpitu; ruční vizuální
kliknutí na iPhonu zatím nebylo potřeba pro důkaz backendové izolace. Při prvním
běžném použití pouze zkontrolovat čitelnost nového přepínače na úzkém displeji.

Další krok: žádná nutná vývojová akce. Pro práci na Knihovně vybrat v Human–Adam
profil `Knihovna`, potvrdit `Přepnout` a pokračovat v jeho vlastním vlákně.

### 2026-07-20 08:28 CEST – Knihovna zaregistrována jako Project v koordinátoru

V neveřejné fázi 1.3 transformace Human–Adam je Knihovna zkušebně
zaregistrována jako pracovní proud `project-knowledge-library` typu `Project`.
Používá své stávající oddělené vlákno, tento TVBCP, handoff
`knowledge_library_article_editing_2026_07_16.md` a izolovaný workspace. Žádný
soukromý identifikátor vlákna ani obsah Knihovny se do Gitu neukládá.

Neveřejný koordinátor mapuje pracovní proud na existující profil a pro samotný
přechod používá dosavadní bezpečnou transakci. Zkušební roundtrip Human–Adam ->
Knihovna -> Human–Adam prošel v testech včetně automatického fast-forwardu obou
čistých cílů z commitnutého lokálního `main`. Neznámý proud a nečistá
rozpracovaná práce zůstávají fail-closed.

Důkaz: cílená sada 38 testů, plná Cockpit sada 870 testů a živý read-only smoke
5/5 prošly. API, existující výběr profilu, vzhled, běžící vlákno, workspace ani
nasazení se v této fázi nezměnily.

Další krok: checkpoint a push fáze 1.3. Teprve potom připravit napojení
existujícího výběru na koordinátor bez změny vzhledu.
