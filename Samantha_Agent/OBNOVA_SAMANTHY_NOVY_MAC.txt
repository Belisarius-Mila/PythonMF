1.2 Co standardní recovery záloha obsahuje

  - Složku PythonMF včetně zdrojů, projektové paměti a přítomné .git.

  - Vybraná data Codexu: config.toml, history.jsonl a strom sessions.

neznamená obraz celého Macu. Symlinky nejsou nezávislou kopií jejich

4. PŘIPRAV NOVÝ MAC
==================
4.1 Základní nastavení

  a) Dokonči nastavení macOS, přihlas se ke svému Apple účtu a ověř internet.
  b) Nainstaluj běžné systémové aktualizace kompatibilní s vybraným Xcode.
  c) Pro soukromá data používej vlastní účet a zapni šifrování FileVault.
  d) Ověř dostatek místa pro zálohu, Xcode/SDK, nová prostředí a média.
  e) U pracovního adresáře ověř, že jde o místní dostupné soubory,
     nikoli pouze cloudové zástupce. Pozor na synchronizaci Plochy iCloudem.

V Terminalu spusť:

    whoami
    printf '%s\n' "$HOME"
    uname -m
    sw_vers -productVersion

Očekávej vlastní domovskou složku; čip arm64 nebo x86_64.
Neměň proměnnou HOME. V dalších příkazech $HOME znamená tvůj skutečný účet.

DŮLEŽITÉ PRO CESTY:
Některé starší spouštěče mají natvrdo /Users/miloslavfalta/...
Stejné krátké jméno nového uživatele obnovu zjednoduší, není však podmínkou.
Při jiném jméně Adam nejprve cíleně zkontroluje aktivní spouštěče,

4.3 Homebrew a správná architektura

Otevři https://brew.sh a použij oficiální instalační příkaz z této stránky.
Instalátor vysvětlí změny a případné vyžádání administrátorského hesla.
Postup ani instalátor nestahuj z náhodného zrcadla. [3]

Potom proveď jeho vypsané kroky pro PATH. Typické umístění:
  Apple Silicon: /opt/homebrew
  Intel:         /usr/local

V aktuálním Terminalu podle příslušného čipu:

    eval "$(/opt/homebrew/bin/brew shellenv)"

nebo na Intelu:

    eval "$(/usr/local/bin/brew shellenv)"

Stejný instalační řádek přidej jen jednou do souboru, který určí instalátor
(obvykle ~/.zprofile). Existující soubor nepřepisuj celý. Ověř:

    command -v brew
    brew --version
    brew --prefix

Nepřenášej starý Intel Homebrew, jeho Cellar ani .venv na Apple Silicon.
Na nepodporovaném starém Intelu může být nutná jiná podporovaná distribuční
cesta; nevynucuj automaticky sestavení celého prostředí ze zdrojů.

4.4 Základní balíčky

    brew install python@3.12 python-tk@3.12 node@24 gh ripgrep
    brew install ffmpeg tesseract tesseract-lang poppler

Odkazy a formule: [4], [5], [6]. Python/Tk je zvlášť; pip tkinter neinstaluje.
Node 24 je zde vybraná LTS řada podobná ověřenému prostředí, ne požadavek
automaticky přejít na každou novou hlavní verzi.

Node@24 je keg-only. Pro aktuální Terminal:

    export PATH="$(brew --prefix node@24)/bin:$PATH"

Jeho konkrétní cestu přidej do svého PATH podle pokynu Homebrew, např.
/opt/homebrew/opt/node@24/bin na Apple Silicon. Nový Terminal musí najít node.
Stejně musí nástroje později najít automaticky spouštěná služba, viz kap. 10.

Kontrola:

    "$(brew --prefix python@3.12)/bin/python3.12" --version
    node --version
    npm --version
    gh --version
    ffmpeg -version
    ffprobe -version
    tesseract --list-langs
    pdftoppm -v
    /usr/bin/screen --version

U Tesseract očekávej eng a ces. Pokud chybí, zkontroluj tesseract-lang.
Instalace FFmpeg sama nedokládá funkčnost konkrétního filmového kodeku;
po obnově ověř skutečný náhled a render na syntetickém médiu.

Alternativa pro Python: oficiální instalace z python.org, viz [7].
Použij jeden vybraný stabilní Python 3.12, s funkčním Tk a certifikáty.
U python.org instalace spusť přiložený Install Certificates.command.
Python 3.12.10 má oficiální universal2 instalátor, ale není nejnovější
bezpečnostní 3.12.x; pro běžnou obnovu preferuj aktualizovanou podporovanou
cestu. Nepřecházej potichu na 3.13/3.14/3.15 jen kvůli novějšímu číslu.

5. PŘIPOJ ZÁLOHU A VYBER DOKONČENÝ SNAPSHOT
=========================================
Připoj externí disk. Ve Finderu otevři SamanthaSecureBackup.sparsebundle
(historicky je na disku Falta). Heslo zadávej jen do systémového dialogu.
Pokud svazek nejde otevřít, neformátuj disk a nevytvářej přes něj nový obraz.

Očekávaná cesta po odemčení:

    /Volumes/SamanthaSecureBackup/SamanthaBackups/snapshots/

Výpis:

    ls -1 "/Volumes/SamanthaSecureBackup/SamanthaBackups/snapshots"

NEVYBÍREJ slepě poslední jméno přes tail -1. Neúspěšný běh může vytvořit
novější nedokončenou složku. Prohlédni kandidáta a zkontroluj manifest.
Pro poslední zde doložený snapshot nastav:

    RECOVERY_SNAPSHOT="/Volumes/SamanthaSecureBackup/SamanthaBackups/snapshots/20261018_210658"
    ls "$RECOVERY_SNAPSHOT"
    cat "$RECOVERY_SNAPSHOT/backup_manifest.txt"

Při budoucí novější záloze nahraď jen ID potvrzeného dokončeného snapshotu.
Očekávej PythonMF/, codex_home/, backup_manifest.txt a recovery návod.
Manifest musí uvádět Profile: recovery a správný zdroj/rozsah.
Profil safe vynechává další citlivá data; není rovnocenný recovery.
Ani recovery neobsahuje vše z kapitoly 1.3. Živé Camino obnovuj z jeho
doplňku, nikoli hledáním starých dat ve stromu PythonMF. Nový recovery
manifest na doplněk odkazuje; snapshot z 18. 10. tento odkaz ještě nemá.

V nejasném snapshotu nic neopravuj a nemaž. Zachovej původní disk jako zdroj.


6. OBNOV PYTHONMF DO PRÁZDNÉHO CÍLE
==================================
6.1 Máš recovery snapshot

    mkdir -p "$HOME/Desktop"
    test -e "$HOME/Desktop/PythonMF" && echo "STOP: cil uz existuje"

Pokud test vypíše STOP nebo je cesta symlink, nepokračuj kopírováním.
Nejprve s Adamem domluv zachování existující složky a nový prázdný cíl.
Nepoužívej mazání, automatické slučování ani rsync --delete.
Jen při potvrzeném neexistujícím cíli pokračuj:

    RECOVERY_PROJECT="$HOME/Desktop/PythonMF"
    mkdir "$RECOVERY_PROJECT"
    rsync -a "$RECOVERY_SNAPSHOT/PythonMF/" "$RECOVERY_PROJECT/"

Koncové lomítko u zdroje je úmyslné. Cílem je přímo PythonMF, nikoli
vnořená složka PythonMF/PythonMF. Kopíruje se i skrytá .git a .env.

Ověř adresáře a čitelnost známého souboru:

    test -f "$RECOVERY_PROJECT/Samantha_Agent/AGENTS.md" && echo "AGENTS OK"
    cmp "$RECOVERY_SNAPSHOT/PythonMF/Samantha_Agent/AGENTS.md" \
        "$RECOVERY_PROJECT/Samantha_Agent/AGENTS.md"
    git -C "$RECOVERY_PROJECT" status --short --branch
    git -C "$RECOVERY_PROJECT" log -1 --oneline

cmp bez výstupu a exit 0 znamená shodu. Příkaz test při úspěchu hlásí AGENTS OK.
Pokud chybí .git, je zdroj neúplný nebo jde o export; Git nekonstruuj naslepo
uvnitř soukromých dat. Ponech obnovu a vyřeš samostatnou kopii repozitáře.

6.2 Máš pouze GitHub, bez recovery dat

Nejdřív přihlášení GitHubu podle kap. 8. Potom při neexistujícím cíli:

    cd "$HOME/Desktop"
    git clone https://github.com/Belisarius-Mila/PythonMF.git

Tím získáš publikovaný kód a git-safe paměť. Nezískáš .env, ignorovaná
soukromá data, kompletní archivy, nepřenesené lokální commity ani Camino
z Library. Prázdný nový vault není důkaz úspěšné obnovy původních dat.

6.3 Porovnej GitHub s obnoveným stavem, ale nezahoď novější lokální práci

    cd "$HOME/Desktop/PythonMF"
    git status --short --branch
    git remote -v
    git fetch origin
    git rev-list --left-right --count main...origin/main

Git remote zkontroluj místně; případnou URL s přístupovým tokenem nesdílej.
Fetch mění jen vzdálené reference, nepřepisuje pracovní soubory.
Výsledek 0 0 znamená shodu. Lokální náskok může být zachráněná nepublikovaná
práce. Při divergenci nebo nečistém stavu zastav integraci a zachovej soubory.
Jen při čisté main bez lokálního náskoku a pouze vzdáleném náskoku lze po
kontrole rozsahu použít git merge --ff-only origin/main. Není to první krok
obnovy. Nepoužívat automatický pull, rebase ani reset --hard.

6.4 Doplněk kódu uložený na SSD dne 19. 10.

Vedle doplňku dat Camina je ve šifrovaném kontejneru uložen Git bundle:

    RECOVERY_CODE_BUNDLE="/Volumes/SamanthaSecureBackup/SamanthaBackups/recovery_updates/SAMANTHA_KOD_DOPLNEK_20261019.bundle"

Tento doplněk obsahuje změny kódu a git-safe dokumentace od projektového
snapshotu 20261018_210658 včetně nového zálohovacího postupu. Jeho výchozí
commit je 2e14eaf244e9633e6fea1b90b3bd35a0f59e38b1. Není to samostatná
záloha celého repozitáře: potřebuje obnovenou historii uvedeného snapshotu.
Soukromá data Camina obsahuje jiný doplněk podle kapitoly 12.

Po obnově projektu ověř bundle a načti jeho větev do oddělené reference:

    cd "$HOME/Desktop/PythonMF"
    git bundle verify "$RECOVERY_CODE_BUNDLE"
    git fetch "$RECOVERY_CODE_BUNDLE" main:refs/remotes/recovery-ssd/main
    git log --oneline main..recovery-ssd/main
    git status --short --branch

Jen po kontrole, na čisté main a při potvrzeném přímém navázání:

    git merge --ff-only recovery-ssd/main

Pokud už máš novější stav z GitHubu, nebo vznikne divergence, nic nevracej
zpět. Zachovej obě historie a rozhodni další integraci s Adamem. Na novém
Macu tím získáš i scripts/backup_camino.py; samotná kopie starého snapshotu
z 18. 10. tento nový program neobsahuje.

================================

10.1 Nejdřív zkontroluj cesty a PATH

Na jiném účtu je Adam musí před použitím cíleně upravit a ověřit. Žádný

PATH s konkrétními ověřenými cestami a CODEX_BIN na výsledek command -v codex.
Na Apple Silicon bývá nutné zahrnout /opt/homebrew/opt/node@24/bin a
/opt/homebrew/bin; nespoléhej na původní /usr/local/bin z Intelu.
Změny plist a jeho načtení provádí Adam jako jeden potvrzený servisní krok;
samotné vyplnění této kapitoly není důkaz, že automatický runtime funguje.

11. TAILSCALE, IPHONE A SSH
=========================
11.1 Tailscale na novém Macu

Nainstaluj oficiální Tailscale a přihlas se do stejné vlastní sítě. [14]

Nejdřív ověř běžný internet, potom Tailscale a nakonec proxy. Na novém Macu
zkontroluj lokální CLI bez zveřejnění výpisu síťových identit:

zjisti místně; nejsou zapsané do tohoto veřejně bezpečného návodu.

11.2 Soukromá HTTPS proxy do jednoho Cockpitu

Teprve po funkčním localhost:8770 a schválení síťové změny použij
registrovaný postup skriptu:

    .venv/bin/python scripts/migrate_cockpit_single_instance.py --apply

Před spuštěním načti jeho aktuální návod a potvrď změnu. Zachovává jediný
místní Cockpit a nastavuje soukromý Tailscale vstup; není to veřejný web.
HTTPS je nutné pro browserové nahrávání mikrofonu. Tailscale certifikát
může zveřejnit jméno stroje v Certificate Transparency, proto nepoužívat

Ověř ze skutečného iPhonu novou HTTPS adresu, stejné rozhraní, nový

12.1 Volba doplňku, ověření a kopie do prázdného cíle

Dne 19. 10. byl celý doplněk 20261019_212828-78238a8a obnoven do nové
soukromé dočasné složky. Všech 1 587 souborů má správné SHA-256, čtyři DB
prošly quick_check a všech 304 originálů souhlasí s mediálními účtenkami.
Identita a obsah archivu se shodují se zdrojem. Z obnovené kopie nebyla
spuštěna druhá služba. To ověřuje souborovou obnovu Camina; instalace
a celková přejímka na skutečném novém Macu zatím neproběhla.

Zvol ID z řádku Camino supplement projektového manifestu, nebo samostatný
doložený doplněk. Novější neúplná složka bez backup_manifest.json není
dokončená záloha. Manifest obsahuje soukromé názvy; nevypisuj ho do chatu.

    RECOVERY_CAMINO_SNAPSHOT="/Volumes/SamanthaSecureBackup/SamanthaBackups/camino_snapshots/20261019_212828-78238a8a"
    export RECOVERY_CAMINO_SNAPSHOT
    test -f "$RECOVERY_CAMINO_SNAPSHOT/backup_manifest.json" && echo "Manifest existuje"

Před kopírováním ověř VŠECHNY soubory a čtyři databáze bez spuštění služby.
Použij již nainstalovaný RECOVERY_PYTHON z kapitoly 4; nepotřebuje knihovny:

    "$RECOVERY_PYTHON" - <<'PY'
    import hashlib, json, os, sqlite3
    from pathlib import Path
    root = Path(os.environ['RECOVERY_CAMINO_SNAPSHOT']).resolve()
    manifest = json.loads((root / 'backup_manifest.json').read_text())
    assert manifest['schema'] == 1 and manifest['scope'] == 'camino-recovery'
    for relative, expected in manifest['files'].items():
        rel = Path(relative)
        path = root / rel
        assert not rel.is_absolute() and '..' not in rel.parts
        assert path.resolve() == path and path.is_file()
        assert path.stat().st_size == expected['bytes']
        with path.open('rb') as stream:
            assert hashlib.file_digest(stream, 'sha256').hexdigest() == expected['sha256']
    assert len(manifest['databases']) == 4
    for relative in manifest['databases']:
        assert relative in manifest['files']
        db = sqlite3.connect((root / relative).as_uri() + '?mode=ro', uri=True)
        try:
            assert db.execute('PRAGMA quick_check').fetchall() == [('ok',)]
        finally:
            db.close()
    print('PASS: SHA-256 vsech souboru a integrita 4 DB')
    PY

Při chybě nepokračuj. Po PASS ověř, že cíl neexistuje ani jako symlink:

    CAMINO_RECOVERY_BASE="$HOME/Library/Application Support/PythonMF/Camino"
    test -e "$CAMINO_RECOVERY_BASE" -o -L "$CAMINO_RECOVERY_BASE" && echo "STOP: cil uz existuje"

Kopíruje se Service/ a potřebný Releases/<release>/Samantha_Agent/.

16. KDYŽ NĚCO NEFUNGUJE
======================
„python3 je jiná verze“:
  Použít konkrétní RECOVERY_PYTHON a .venv/bin/python; neměnit systémový Python.

„pip importuje jinam / modul chybí“:
  Ověřit .venv/bin/python -m pip --version a vybraný interpreter VS Code.
  Instalovat do stejného prostředí, ne do systémového Pythonu.

„SSL: CERTIFICATE_VERIFY_FAILED“:
  U python.org dokončit Install Certificates.command, ověřit certifi a
  správný CA store. Nevypínat kontrolu TLS a nepřidávat univerzální insecure.

„bad CPU type / Exec format / binárka z Intelu“:
  Nainstalovat nativní program a znovu vytvořit příslušné prostředí.
  Neobnovovat celý starý /usr/local ani venv kopírováním.

„Cockpit funguje ručně, ale po přihlášení ne“:
  Zkontrolovat cesty, pracovní adresář, CODEX_BIN, PATH a macOS oprávnění
  NOVÉ vlastní služby. Launchd nemá stejné prostředí jako Terminal.

„thread not found / nelze navázat Adama“:
  Zachovat původní soukromý stav; obnovit relevantní sessions jen po kontrole.
  Použít nové vlákno s handoffem. Starý socket nebo PID se neobnovuje.

„Na iPhonu nejde 127.0.0.1“:
  To je telefon. Použít novou soukromou HTTPS adresu Macu přes Tailscale.

„Port 8766/8767/8770 je obsazený“:
  Zjistit vlastníka; nepoužívat plošné kill. 8766 ScanDocu, 8767 Camino,
  8770 Cockpit. Nezakládat druhý server jako obcházení problému.

„Camino hlásí jinou epochu / chybí média“:
  Zastavit další změny. Ověřit úplnost a identitu archivu. Telefon nemaž,
  neprováděj nový čistý bootstrap a neresetuj jeho journal.

„Kde hledat zálohu Camina?“:
  Ve vlastním snapshotu 20261019_212828-78238a8a v camino_snapshots,
  nikoli uvnitř staršího projektového snapshotu. Kapitoly 1.4 a 12 uvádějí
  dokončenou zálohu i její ověřenou souborovou obnovu.
